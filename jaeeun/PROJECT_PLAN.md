# Segmentation 기반 헤어·의상 가상 피팅 프로젝트 계획

> 구현하여 영상까지 검증을 마쳤으나, 그래픽 가속이 없어 속도가 실사용 수준에 못 미친다.

## 1단계. 개발 환경 및 프로젝트 구조

- **목표:** 협업 파일 충돌을 막고 동일한 환경에서 실행한다.
- **사용 프로그램:** Python 3.11, Git, FFmpeg, Streamlit.
- **사용 라이브러리:** PyTorch, Transformers, Diffusers, OpenCV, Pillow, NumPy, SAM 2.
- **데이터셋:** 사용하지 않음.
- **산출물:** `jaeeun/` 패키지, `.venv`, `requirements.txt`, `SETUP.md`.

## 2단계. 데이터셋 조사 및 전처리

- **목표:** 이미지와 영상을 모델 입력 규격으로 통일한다.
- **전처리:** 이미지 비율을 유지한 resize 및 padding, 영상 프레임 추출. 추출 시 정수 단위로만
  프레임을 건너뛸 수 있으므로 실제 샘플링 비율(예: 30fps에서 4프레임마다 → 7.5fps)을 기록해
  재조합 때 그대로 사용한다.
- **데이터셋 사용 방침:** 이 프로젝트는 **모델을 학습시키지 않는다.** 세 모델 모두 공개 가중치를
  그대로 사용하므로 학습용 데이터는 필요하지 않다. 데이터셋은 **정량 평가를 위한 정답 라벨**
  용도로만 쓴다.
  - **LIP 또는 ATR 일부 (100~200장):** 분할 정확도(IoU, Dice)를 숫자로 제시하기 위한 정답 라벨.
    현재 유일하게 필요성이 확인된 데이터셋.
  - **자체 동의 데이터:** 실제 사용 환경의 각도·밝기·가림 변화 평가. 촬영 조건은 정면 유지,
    고정 카메라, 얼굴이 화면 세로의 1/3 이상.
  - **CIHP / ModaNet / DeepFashion2 / VITON-HD / SA-V:** 학습을 하지 않으므로 현 범위에서는
    사용하지 않는다.

## 3단계. 이미지 부위 분할

- **목표:** 입력 인물에서 머리카락, 얼굴, 상의 등 편집 부위의 마스크를 생성한다.
- **주 모델:** `fashn-ai/fashn-human-parser`.
  - SegFormer-B4 기반 공개 가중치.
  - 얼굴, 머리카락, 상의, 드레스, 바지, 팔, 손 등 18개 클래스를 출력.
- **SAM 2 용도:** Human Parser가 만든 경계를 사용자가 클릭이나 박스로 보정할 때 사용.
- **데이터:** FASHN 공식 샘플로 동작 확인 후 LIP/ATR 및 자체 이미지로 정량·정성 평가.
- **평가:** 클래스별 IoU, Dice, 추후 Boundary F1.
- **현재 결과:** 공식 샘플에서 얼굴, 머리카락, 상의, 팔, 손, 바지, 다리 등의 마스크 생성 완료.

## 4단계. 이미지 편집

두 가지 방식을 쓰며, 목적이 다르다.

### 4-1. 색 변경 (구현 완료)

- **방식:** OpenCV LAB 색공간에서 색조만 교체하고 명도 채널은 원본을 유지한다.
- **이유:** 머릿결과 그림자가 그대로 남아 자연스럽고, 모델을 거치지 않아 수 초 만에 끝난다.
- **적용 부위:** 머리, 상의. 단독 또는 동시 적용.
- **한계:** 명도를 바꾸지 않으므로 어두운 머리를 밝은 색으로 바꿀 수 없다.
- **검증 결과:** 편집 영역 밖의 픽셀 변화량 0.

### 4-2. 헤어스타일 변경 (구현 완료)

- **모델:** HairFastGAN (AIRI Institute, NeurIPS 2024, MIT).
  - StyleGAN2 FS 잠재공간에서 동작하며, 내부에 e4e / FeatureStyleEncoder / CtrlHair Shape
    Branch / RotateModel / SEAN / ClipBlendingModel / PostProcessModel / BiSeNet을 포함한다.
  - **텍스트가 아니라 참조 사진으로 지시한다.** 원하는 머리 모양이 담긴 사진 한 장을 주면
    그 모양과 색을 함께 가져온다.
- **전처리:** dlib 68점 검출로 얼굴을 FFHQ 규격 1024 정사각으로 정렬한다. 얼굴을 찾지 못하면
  그 프레임은 처리할 수 없다.
- **환경:** 요구 라이브러리가 주 환경과 충돌하므로 별도 가상환경에 두고 하위 프로세스로
  호출한다. 이 환경이 없어도 나머지 기능은 정상 동작한다.
- **한계:** 결과가 얼굴을 잘라낸 정사각형으로 나오며, 원본 화면 복원은 미구현. 정면에서 좌우
  40도 정도까지만 동작하고 뒤통수는 원리상 불가능하다.

### 4-3. Diffusion Inpainting (보류)

- **모델:** `stabilityai/stable-diffusion-2-inpainting` (OpenRAIL++).
- **실측 결과:** 사진 1장에 6분 24초. 편집 영역이 머리뿐인데도 얼굴이 다른 사람이 되고 눈썹
  주변에 얼룩이 생겼다. **헤어스타일 변경 목적으로는 4-2가 모든 면에서 낫다.**
- **처리:** 가중치는 보관하되 사용하지 않는다. 향후 의상 종류 변경을 하게 되면 재검토한다.

### 4-4. 생성 결과 기반 색 지정 (계획, 다음 작업)

현재 헤어스타일 변경은 참조 사진의 **모양과 색을 함께** 가져오므로, "단발 모양 + 원래 검은
머리" 같은 조합이 불가능하다. 참조 사진이 금발이면 결과도 반드시 금발이 된다.

- **방식:** HairFastGAN이 생성한 결과에 부위 분할을 실행해 **새 머리 마스크**를 얻고, 그
  마스크 안쪽에 원하는 색을 적용한다.
- **원본 마스크를 쓸 수 없는 이유:** (1) 긴 머리를 단발로 바꾸면 원래 머리가 있던 자리가
  배경이 되고, (2) 앞머리가 생기면 이마였던 곳이 머리가 되며, (3) 결정적으로 생성 결과는
  얼굴을 잘라 정렬한 1024 정사각형이라 원본과 픽셀이 대응하지 않는다.
- **검증된 전제:** 생성 이미지에 부위 분할이 동작하는지는 이미 확인했다. 4개 스타일 × 11
  프레임의 생성 결과 전부에서 머리 영역을 정상적으로 잡아냈다(6-2의 색 폭 측정에 사용).
- **영상일 때:** 프레임마다 분할하면 마스크 경계가 떨리므로 **생성 결과 프레임들에 SAM 2를
  적용해 마스크를 안정화**한다. 6-2에서 확인된 색 흔들림 문제와 같은 배관을 쓴다.
- **한계:** 색 변환이 명도를 보존하므로 밝은 금발 결과를 검정으로 바꾸면 회색빛이 된다.
  어두운 머리 참조를 쓰거나 명도 보정을 별도로 추가해야 한다.
- **의의:** 이 작업으로 부위 분할·SAM 2·색 변환이 **헤어스타일 경로에도 투입**되어, 현재
  서로 무관한 두 갈래가 하나로 이어진다.

## 5단계. 영상 마스크 전파 (색 변경 경로)

- **목표:** 첫 프레임에서 얻은 머리·상의 마스크를 전체 프레임에 안정적으로 전달한다.
- **모델:** SAM 2.1 Hiera Small (Apache 2.0).
- **처리:** 프레임 추출 → 첫 프레임 Human Parsing → **파서 마스크를 그대로 seed로 입력** →
  전체 프레임 전파. 클릭 지점이 아니라 마스크로 시작하므로 파서가 찾은 경계를 그대로 이어간다.
  머리와 상의는 객체 id를 나눠 **1회 전파로 동시에** 처리한다(프레임별 인코딩 비용 공유).
- **적용 범위:** 색 변경 경로에만 사용한다. 헤어스타일 변경은 프레임마다 머리를 새로 생성하므로
  추적할 원본이 없고, 모델이 자체 분할(BiSeNet)을 갖고 있어 SAM 2를 쓰지 않는다.
- **예정 용도:** 4-4에서 생성 결과의 머리 마스크를 프레임 간 안정화하는 데 사용한다.
  헤어스타일 결과를 원본 화면에 되붙일 때의 경계 추적에도 쓸 수 있다.

## 6단계. 시간 일관성

경로마다 방식이 다르다.

### 6-1. 색 변경 경로

- **방식:** 이전 프레임 결과를 optical flow로 현재 프레임에 정렬한 뒤 혼합한다.
- **핵심 제약:** 혼합을 **편집 영역 안으로만 제한**한다. 화면 전체에 적용하면 흐름 추정 오차가
  얼굴과 배경에 잔상으로 남는다. 제한 후 비편집 영역 변화량 0을 확인했다.
- **출력:** 실제 샘플링 비율로 FFmpeg 재조합, 원본 오디오 결합.

### 6-2. 헤어스타일 경로

- **방식:** 프레임마다 독립적으로 생성한다. 각 프레임의 고개 각도에 맞는 머리를 얻으려면
  기준 프레임 하나를 밀어 붙이는 방식으로는 안 되기 때문이다.
- **실측:** 프레임 간 변화량이 원본 대비 0.90~0.98로, 4개 스타일 모두 원본보다 안정적이었다.
  별도 보정을 넣지 않은 상태의 값이다.
- **남은 문제:** 머리 영역만 따로 재면 색조가 영상 내내 흔들린다(색 폭 27~56). 화면 전체
  평균으로는 얼굴·배경이 원본 그대로라 이 흔들림이 가려진다.
- **개선 방향:** (1) 4-4의 배관을 그대로 써서 프레임별 머리 색을 영상 전체 중앙값으로
  정규화한다 — 저비용이며 4-4와 부품을 공유한다. (2) 잠재코드를 프레임 간에 평활화하면
  색과 모양이 함께 안정되지만 격리 환경 내부 수정이 필요하다.

## 7단계. 웹 서비스 통합 (구현 완료)

- **입력:** 사진 또는 짧은 영상 업로드.
- **기능 선택:** 헤어스타일 변경 / 머리·상의 색상 동시 변경 / 머리 색상만 / 상의 색상만 /
  분할 마스크 확인.
- **헤어스타일 지정:** `data/jaeeun/hairstyles/` 폴더를 읽어 선택지를 구성하며, 사용자가 직접
  사진을 올릴 수도 있다. 고른 참조 사진은 미리보기로 표시한다.
- **진행 표시:** 영상 처리는 프레임별 진행률을 표시한다. 그래픽 가속이 없으면 수십 분이
  걸리므로 멈춘 것과 구분이 필요하다.
- **결과 유지:** 결과를 세션에 보관해 다른 항목을 조작해도 사라지지 않는다.
- **출력:** before/after 비교, 영상 재생 및 내려받기.
- **미구현:** 헤어스타일 결과의 원본 화면 복원, 모양과 색의 분리 지정.

## 8단계. 최종 평가

### 측정한 것

| 항목 | 결과 |
|---|---|
| 색 변경 시 비편집 영역 보존 | 픽셀 단위 동일 (변화량 0) |
| 헤어스타일 프레임 간 변화 (전체 화면) | 원본 대비 0.90~0.98 |
| 헤어스타일 프레임 간 변화 (머리 영역) | 색 폭 27~56 — 개선 필요 |
| 얼굴 검출 성공률 | 정면 유지 영상 100%, 뒤돌아보는 영상 45% |
| 처리 시간 | 영상 색 변경 22프레임 2분 30초, 헤어스타일 1프레임 2~5분 |

### 남은 평가

- **분할 정확도:** IoU, Dice, Boundary F1. 정답 라벨 데이터가 필요하며 아직 측정하지 않았다.
- **시간 일관성:** 현재 지표는 이웃 프레임의 단순 차이라 **정상적인 움직임과 깜빡임을 구분하지
  못한다.** optical flow로 정렬한 뒤 남는 차이를 재는 방식으로 교체해야 한다. 정렬 기능은
  이미 6-1에 있으므로 재사용 가능하다.
- **사용자 평가:** 자연스러움, 동일 인물 유지, 사용 의향 5점 척도.
- **개인정보:** 자체 사진·영상은 사전 동의, 목적·보관기간 고지, 평가 종료 후 삭제. 인물이
  담긴 원본은 저장소에 포함하지 않는다.

## 9단계. GPU 환경 이전 (VESSL)

현재 남은 성능 병목은 전부 계산 장비에 있다. 알고리즘이나 구현의 문제가 아니므로, 코드를
바꾸지 않고 실행 환경만 옮기면 해결된다.

- **대상:** 헤어스타일 변경 경로. 색 변경은 이미 충분히 빠르므로 옮길 필요가 없다.
- **예상 효과:** 사진 1장 2~5분 → 수 초. 영상 11프레임 24~34분 → 1~2분. 10초 영상(80프레임)
  4~7시간 → 5~10분.
- **명세:** `vessl/hairstyle.yaml`. `vessl run -f vessl/hairstyle.yaml`로 실행한다.

### 옮기기 전에 해결한 것

| 문제 | 조치 |
|---|---|
| 모델 코드 수정본이 저장소에 없어 새 환경에서 재현 불가 | `jaeeun/patch_hairfastgan.py`로 자동화 |
| CPU 강제 코드가 GPU에서도 동작해 가속을 무력화 | 장치를 감지해 GPU가 있으면 원래 경로를 쓰도록 변경 |
| 컴파일 도구가 없는 GPU 호스트에서 CUDA 커널 참조 실패 | 커널이 없으면 장치와 무관하게 순수 PyTorch 경로를 쓰도록 분기 수정 |
| 합성 모듈이 CPU 전용으로 고정 | 장치에 따라 GPU 사용 여부를 결정 |

### 준비 사항

1. 가중치 7.3GB를 VESSL 스토리지에 한 번 업로드한다. 실행할 때마다 내려받으면 매번 25분이
   낭비된다.
2. 처리할 프레임과 참조 사진을 업로드한다.
3. 명세의 `import`/`export` 경로를 실제 스토리지 경로로 바꾼다.
4. GPU 사용 시간만큼 과금되므로 크레딧을 먼저 확인한다.

### 이후 선택지

- **배치 실행(현재 명세):** 프레임을 올리고 결과를 받는 방식. 데모 결과물 생성에 적합하다.
- **웹 화면까지 이전:** VESSL에서 Streamlit을 서비스로 띄우면 실시간 데모가 가능하다. 다만
  격리 환경 구조를 다시 설계해야 한다.
